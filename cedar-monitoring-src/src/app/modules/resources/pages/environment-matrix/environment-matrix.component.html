Set on the host, outside the Java configuration model

Set on this host and absent from CedarEnvironmentVariable, so they cannot appear in the matrix above or in any service's report. This does not mean nothing reads them. Most are consumed by the infrastructure layer, which never passes through the Java model and has no reason to — nginx config generation, docker-compose, container init scripts such as Mongo's user setup, and the shell profiles themselves.

What the list is good for is the exceptions: a variable read by Java through System.getenv, which belongs in the model and is invisible until it is added — the worker's log aggregation settings were exactly that — and a variable that outlived whatever used to read it and is now exported for nothing. Neither can be told apart from an ordinary infrastructure variable without going and looking; this page can only say which names the model does not account for.
